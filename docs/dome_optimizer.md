# Dome optimizer

The dome optimizer supports open-cap magnet geometries using finite cuboid field
calculations, optional mutual demagnetization, least-squares orientation seeding,
a smoothed worst-case objective, and a two-angle orientation model.

## Architecture

The dome-specific modules are imported through their full package paths rather
than re-exported from the top-level package `__init__` files. This keeps the
top-level public API limited to the established FieldSmith interfaces.

## Components

| Module | What it does | What it reuses |
|---|---|---|
| `field_simulations/cuboid.py` | Closed-form field of uniformly magnetized cuboids, evaluated directly, with optional per-magnet body rotation | Signature, validation and chunking style of `rectangular_prism.py` |
| `geometry/cube_axes.py` | Per-magnet body frame with local +z along the magnetization | — |
| `field_simulations/demagnetization.py` | Mutual coupling matrix and the first-order remanence correction | The cuboid kernel above |
| `objectives.py` | Log-sum-exp smoothed peak-to-peak, exact peak-to-peak, rms, mean-field band, and a `TrainLoop`-compatible callable | The `loss_fn` contract, `metrics.py` conventions |
| `geometry/dome.py` | Cap geometry on a dome shell and magic-sphere initialization | `MagnetConfiguration`, the builder shape of `halbach_system.py` |
| `geometry/lsq_seed.py` | Least-squares seeding of orientations for any geometry and target direction | The dipole kernel's conventions |
| `models/dome/model.py` | Two-angle, optionally demag-aware model | Subclasses `SingleRingHalbachModel`; same `forward()` output contract |
| `evaluation/core.py` | Scores a stored configuration under an explicitly chosen physics | `objectives.py`, both field kernels |
| `configurations/dome_config.py` | `.cfg` loader for the above | Mirrors `HalbachSystemConfig` |

The workflow is configured through `configs/dome_geometry.cfg` and started with
`scripts/run_dome_optimisation.py`. Optimization, logging, and visualization use
the common `TrainLoop`, `WandbLogger`, and visualization modules.

## Design notes

**Mutual demagnetization.** In a densely packed array, each magnet is exposed to
the fields generated by the other magnets. This can reduce its effective
magnetization relative to the ideal-source model.
`demagnetization.py` puts that physics inside the loop:
`DomeAngleModel.create_magnet_vectors()` applies the correction before the field is
evaluated, so it affects every gradient step rather than only post-processing the
result. The correction is a linear solve against a constant coupling matrix, so it
is exactly differentiable; `torch.autograd.gradcheck` over the whole chain is part
of the suite.

**Physics-model comparison.** `evaluation.evaluate_configuration` can evaluate a
stored configuration with a selected physics model. For example, a configuration
optimized with ideal magnets can be evaluated with mutual demagnetization enabled
to quantify the sensitivity to that modeling assumption.

**The objective needs a gradient everywhere.** `metrics.homogeneity_loss` is an
exact max−min, so its gradient touches only the two extremal ROI points and
progress stalls. The log-sum-exp form spreads gradient over every point near the
extremes and sharpens as `alpha` ramps.

**Magnetization must be able to leave the plane.** `SingleRingHalbachModel` builds
orientations as `(cos, sin, 0)`, so a cap is unrepresentable. `DomeAngleModel` adds
the polar angle and is a strict generalization: with `theta = pi/2`, the dipole
kernel and no susceptibility it reproduces the parent model's field.

**Seeding.** `DomeGeometry.build()` sets orientations from the magic-sphere rule,
the 3-D form of the ring rule the other builders use, so the geometry is complete
on its own. That rule is local and assumes a full spherical shell, which an open
cap is not, so the runner reseeds with `geometry/lsq_seed.py` before optimizing.

The field is linear in the remanence vectors, so a uniform target can be expressed
as a least-squares problem over all magnets and all ROI points. It accounts for
the discrete positions, the extent of the ROI and the missing part of the shell.
Its unconstrained solution gives every magnet its own moment magnitude, which an
array of identical magnets cannot build, so the solve carries that constraint
instead of projecting onto it afterwards. It needs only positions and a target
direction, so tilted targets and arbitrary position clouds are equally admissible.
Mirror symmetry is opt-in and exact. The ROI is known only to the point sampler,
so the runner solves the seed after building the model and rebuilds with the
result. At a few thousand magnets this costs well under a second, once per run.

**Quasi-static body axes.** `cube_axes_from_directions` picks the two transverse
axes with an `argmin`, which jumps where two direction components cross in
magnitude. `DomeAngleModel.body_axes()` therefore detaches the frame and rebuilds
it every step: consistent with the current design at all times, without
differentiating through a discrete switch. The frame follows the design
orientation, not the corrected moment — the pocket is machined for the nominal
angle, and demagnetization shifts the moment slightly but not the body.

**Self-coupling** is removed by zeroing the diagonal blocks, which for a cube is
exactly its +2/3·Br self field. **Positions are frozen**, as in the parent model,
so the coupling matrix is built once in `__init__` and reused.

## Precision

The cuboid kernel is gated in the suite against
`calc_b_at_points_rect_prism_potential` for both axis-aligned and rotated bodies,
and against the dipole kernel in the far field; the two formulations are
independent, one a direct closed form and one an autograd of the scalar potential.

Two settings are deliberate. `eps` in the cuboid kernel defaults to `1e-20`: it is
added inside `log(dy + r)`, whose argument cancels for points roughly on a face
normal, where a larger value costs significant accuracy. And FieldSmith defaults to
float32, which the exact kernels do not carry far enough for a result quoted in
ppm — the runner offers `--double-precision`, which should be on for any such run.
The least-squares seed decides this for itself and always solves in float64.

## Current limitations

The dome optimizer does not currently include collision/SAT verification,
projection to a buildable lattice, `B = G·m` precomputation, low-rank operators,
an augmented-Lagrangian B0 constraint, or a multi-cycle production chain with
checkpointing. Field strength is constrained with a soft band. Unlike a hard
floor, this does not allow an infeasible field-strength constraint to dominate the
homogeneity gradient indefinitely.

## Running it

```bash
python scripts/run_dome_optimisation.py --double-precision --wandb-mode disabled
```

The supplied configuration is a demonstration with 368 magnets and an ROI above
the aperture plane; it is not intended as a production design.
